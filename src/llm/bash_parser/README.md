# bash_parser — native Windows Git Bash compatibility kernel

`kimix::llm::bash_parser` is the complete native C++ port of the authoritative
Python reference `kimi-agent/bin/kimix_native/shell_compat/*` behind
`fix_bash_command` (the `_shell_compat` facade).  It is compiled into
`kimix-llm` (`add_files("llm/bash_parser/*.cpp")` in `src/xmake.lua`); no new
library target and no third-party dependency.

## Public API (`bash_parser.h`, namespace `kimix::llm::bash_parser`)

| Entry | Reference equivalent |
|---|---|
| `fix_bash_command(command)` | `bash_core.fix_bash_command` → `translator.translate` |
| `fix_bash_command(command, FixOptions{temp_dir})` | same, with `_windows_temp_dir` overridden (the reference test-suite monkeypatch, as an explicit parameter) |
| `bash_compatibility_prelude()` | `bash_core.bash_compatibility_prelude` (incl. the `sys.platform == "win32"` gate → `KIMIX_PLATFORM_WINDOWS`) |
| `process_unquoted(command)` | `unquoted._process_unquoted` |
| `BashFix` | `bash_core.BashFix` frozen dataclass: value type, read-only accessors, value equality |

The kernel always applies the Windows Git Bash transformation — no app-layer
OS gate (the reference `fix_bash_command` itself has none; only the
`bash_compatibility_prelude` keeps the reference platform behavior).

### BashFix byte/report contracts (preserved exactly)

- Report lists are in source-discovery order.
- `replacements` retains repeated discoveries; fallback definitions are
  deduplicated separately for the prefix (`dict.fromkeys` order).
- `unsupported` is first-occurrence deduplicated and, by itself, does not make
  `changed()` true.
- `changed()` = replacements ∨ path_changes ∨ shell_wrappers ∨ nul_fixes ∨
  cmd_conditional_fixes.
- `warning()` preserves reference wording, punctuation, backticks, ordering
  and the unsupported-reason lookup.  Sections ordered: unsupported,
  fallbacks, paths, shell wrappers, nul, cmd control flow; joined by `" "`.
- An unchanged result has the original bytes and empty metadata/warning;
  embedded NUL and non-ASCII bytes are never truncated or normalized.

## Coordinate & depth policy

- All offsets are UTF-8 **byte** offsets.  Recognized shell syntax is ASCII;
  non-ASCII source is opaque and copied byte-for-byte.
- Python `str.isdigit`/`isalpha`/`isalnum`/`str.upper` in path rules are
  reproduced with **full parity** via generated Unicode range tables
  (`unicode_class.inc`, from `scripts/gen_bash_fix_data.py
  --bash-parser-unicode`): Python's exact `isalpha`/`isalnum` codepoint ranges
  (binary-searched) and the `str.upper()` delta table for the `/c/`
  drive-letter rewrite.  Characters are decoded as UTF-8 codepoints, so
  multi-byte path words (`\tmp\ycafé`, `/á/` → `"Á:/"`) rewrite identically to
  the reference.  Malformed/overlong UTF-8 bytes stay opaque (never
  classified), matching the reference's treatment of undecodable input.
  Locale-dependent C `isalpha` is never used on signed bytes.
- Depth: the reference bounds `_scan_range`/`_find_matching` recursion with
  `_MAX_NESTING_DEPTH = 1024` and catches `RecursionError` as pass-through.
  The native scanner keeps the same 1024 budget but runs nested command
  contexts on an **explicit worklist of heap frames**, so 250-level and
  2,000-level nesting cannot overflow the native stack; beyond the budget the
  region stays byte-for-byte (the conservative outcome).
- The IR parser uses the same worklist model (`_drain_tasks` port).

## Temp-dir handling

`FixOptions.temp_dir` overrides the `/tmp` mapping spelling (deterministic
tests use e.g. `C:/Temp`).  Empty = host discovery equivalent to
`tempfile.gettempdir()`: `%TEMP%`, then `%TMP%`, then `C:\Temp`; backslashes
normalized to `/`; non-throwing; never empty.

## Data regeneration

```
python scripts/gen_bash_fix_data.py --bash-parser-data \
    --reference D:/kimi-agent/bin/kimix_native/_shell_compat.py
python scripts/gen_bash_fix_data.py --bash-parser-goldens \
    --reference-root D:/kimi-agent
```

- `--bash-parser-data` rewrites `src/llm/bash_parser/fallback_data.inc`
  (complete `_FALLBACK_BODIES` incl. GNU `g*` aliases + netcat/htop shares,
  `_FALLBACKS` guarded definitions, `_UNSUPPORTED_BODIES`,
  `_FALLBACK_COMMAND_WRAPPERS`).
- `--bash-parser-goldens` rewrites `tests/unit/llm/bash_parser_goldens.inc`
  from the authoritative `bash_core.fix_bash_command` with the fixed temp
  spelling `C:/Temp` (full command bytes + every metadata list + warning +
  `process_unquoted`); the corpus is AST-mined from the reference test suite
  (`--reference-root`) plus robustness/malformed extras.
- `--bash-parser-path-goldens` rewrites
  `tests/unit/llm/bash_parser_path_goldens.inc` (pure path/nul primitives).
- `--bash-parser-rule-goldens` rewrites
  `tests/unit/llm/bash_parser_rule_goldens.inc` (pure wrapper/cmd rule
  functions).
- `--bash-parser-unicode` rewrites `src/llm/bash_parser/unicode_class.inc`
  (Python `str.isalpha`/`isalnum` codepoint ranges + the `str.upper()` delta
  table for the `/c/` drive-letter rewrite).
  Generation is a development-time reproducibility tool only — normal xmake
  builds never require Python or the reference checkout.

## Tests

Registered individually in tests/xmake.lua (add_deps("kimix-llm")):

- `test_bash_parser` — the public API: the 1,272-row differential golden
  battery (full BashFix tuple + `process_unquoted` for every row) plus
  BashFix value-semantics / NUL-and-non-ASCII pass-through tests.
- `test_bash_parser_lexer` — the lossless tokenizer (token/part tiling,
  spans, inner ranges, operator tables, comments, heredoc markers, oracle
  equivalence, malformed/deep-nesting termination).
- `test_bash_parser_shell_ir` — models/parser: lossless reconstruction
  (`render_source(parse(s)) == s`), command-position classification, heredoc
  semantics, nested contexts, wrapper hints, embedded scripts, iterative
  depth handling.
- `test_bash_parser_paths` — pure path/null-device primitive goldens
  (`path_replacement`, `windows_path_replacement`, `git_bash_abs_path_replacement`,
  `normalize_windows_path`, `quote_path_word`, `is_effective_nul_word`, …).
- `test_bash_parser_rules` — pure wrapper/cmd rule-function goldens
  (`wrapper_step`, `classify_pattern_option`, `plausible_script_file`,
  `cmd_cmp_side`, `build_cmd_cmp`, `split_top_eq`, `cmd_if_branch_ok`,
  `cmd_for_item_ok`, `cmd_body_has_bare_ampersand`, `at_boundary_ok`).
- `test_bash_parser_e2e` — host-gated real Git Bash execution (fallbacks
  run, nested exported functions survive child shells, Windows paths execute,
  `nul` files are not leaked, cmd branches/loops preserve interpreter
  context); skips cleanly when no usable Bash exists.

The scanner/wrapper/cmd/heredoc end-to-end behavior is locked byte-for-byte by
the `test_bash_parser` golden battery (each golden row is the complete result
tuple of the reference `fix_bash_command`), so there are no separate
`test_bash_parser_wrappers`/`_cmd`/`_unquoted`/`_heredoc` binaries — their
reference suites map onto the goldens + the pure-rule goldens above (see the
traceability table).

## Deliberate exclusions (plan §1)

- **PowerShell**: `pwsh_fix.py`, `pwsh_transform.py` and PowerShell-only
  tests (including root `test_bash.py` classes that exercise PowerShell
  despite `TestBashFix...` names).
- Tool/agent integration: bash executable discovery, agent config, tool
  selection, subprocess payloads, background tasks, output filtering, RTK
  rewriting; no changes to src/builtin_tools/bash_tool.* or to the legacy
  runtime src/runtime/parse/shell_scanner.cpp BASH_FIX mode.  The kernel itself
  IS exposed to Python through src/runtime/py/py_bash_fix.cpp, which binds the
  public API as the runtime_py.bash_fix submodule
  (fix_bash_command / bash_compatibility_prelude / process_unquoted); the
  kimi-agent shim bin/kimix_native/_shell_compat.py uses it as the native path
  behind the same three entry points, with this port's reference as the
  KIMIX_NATIVE=0 fallback.
- **App-layer `sys.platform` gate**: the C++ entry always applies the Git
  Bash kernel (the reference kernel does too); non-Windows no-op tests that
  belong to the app wrapper are not kernel tests.  Only
  `bash_compatibility_prelude` keeps the reference platform behavior.
- **Python facade compatibility**: the 195-name `__all__`, dataclass
  mechanics, monkeypatch implementation, object identity (`source is self.s`
  is modeled as "no edits recorded → return original bytes + reuse heredoc
  event positions"), and late-binding facade lookups
  (`_windows_temp_dir_from_namespace` → `FixOptions.temp_dir`).
- **IR-only restatements**: `ir_command.py` and the `translator.py`
  `RuleDispatcher`/`TranslationContext`/`EditPlan` skeleton exist in the
  reference to prove the IR slots 4–8 equal the live scanner byte-for-byte.
  The native port keeps ONE flow (the live scanner) and the equivalent
  primitives (`ScanReports`, sorted one-pass splice render, overlap-free edit
  recording); the dispatcher object model is not duplicated.  The lossless IR
  itself (`spans`/`models`/`lexer`/`parser`) IS ported with its tests.
- **JSON corpus runner** in `test_bash_e2e.py` (`tests/bash/cases.json` is
  absent); its concrete cmd execution tests are ported as host-gated Git Bash
  tests.  Network-dependent, service-mutating, process-killing, clipboard and
  other host-state-changing cases stay transformation/golden tests only.
